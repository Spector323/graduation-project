## Слайд 2 — Актуальность

- Ресторанный бизнес — одна из самых конкурентных сфер
- Многие заведения до сих пор используют бумажные блокноты и Excel
- Готовые решения (R-Keeper, iiko) дорогие и сложные для малого бизнеса
- Нужна простая, доступная система: приём заказов, оплата, склад, отчёты

**Цель:** Разработать веб-систему для автоматизации работы ресторана, кафе или столовой

---

## Слайд 3 — Функциональность

- **POS-терминал** — касса с поиском блюд, корзиной, модификаторами, оплатой
- **Управление меню** — категории, блюда, цены, ингредиенты, рецепты
- **Склад** — учёт ингредиентов, контроль остатков, минимальные запасы
- **Заказы** — создание, отправка на кухню, смена статусов (готовится → готов → выдан)
- **Бронирование столов** — клиенты, даты, статусы брони
- **Аналитика** — выручка, популярные блюда, статистика по сменам
- **Ролевая модель** — администратор, официант, повар, кассир
- **Авторизация** — логин/пароль + быстрый вход по PIN-коду

## Слайд 4 — Архитектура

```
Клиент (браузер)
       │
       ▼
  Next.js Frontend     ← React + TypeScript + Tailwind
  (SSR + Client components)
       │
  ─────────── REST API / Socket.IO ───────────
       │
       ▼
  Express Backend      ← Node.js + JWT
       │
       ▼
  Prisma ORM
       │
       ▼
  PostgreSQL
```

**Особенности:**
- Серверный рендеринг (SSR) для SEO и скорости
- WebSocket (Socket.IO) для real-time обновлений на кухне и у официантов
- REST API для стандартных CRUD операций
- JWT-токены для защиты маршрутов

## Слайд 6 — База данных (основные сущности)

- **Establishment** — заведение (тип: ресторан, кафе, столовая)
- **User** — сотрудник (роль: ADMIN, WAITER, COOK, CASHIER)
- **RestaurantTable** — стол (статус: свободен/занят/забронирован)
- **MenuCategory / MenuItem** — категории и блюда
- **Ingredient / RecipeItem** — ингредиенты и рецептура
- **ModifierGroup / Modifier** — модификаторы (размер порции, добавки)
- **Order / OrderItem** — заказы (статус: новый → готовится → готов)
- **Reservation** — брони (статус: подтверждена/отменена)
- **Shift** — смена кассы

Схема: связанные таблицы через внешние ключи, уникальные индексы, каскадное удаление.
